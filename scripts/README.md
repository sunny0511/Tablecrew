# scripts/

One-off ops scripts, data migrations, and seed scripts, per `docs/ENGINEERING_GUIDELINES.md`'s repository structure. Its own small npm package (own `package.json`/`tsconfig.json`/`node_modules`), independent of `functions/` and `firestore/test/rules/`.

**`seed_staging.ts`** (referenced by `docs/TESTING.md`'s "Test Data Management" section) — landed in Milestone F1, alongside the core data layer it seeds. Populates the real `tablecrew-staging` Firebase project with a small, realistic, entirely synthetic set of Users/Crews/Tables, so staging is never empty and never contains real user data. Refuses to run against anything other than `tablecrew-staging` (never dev, never prod) and requires an explicit `--yes` flag — see the file's own top-of-file comment for the full safety rationale. Run via `npm run seed:staging -- --project=tablecrew-staging --yes` after `npm install` in this directory.

**`grant_admin.ts`** (Milestone F7, ADR 0007) — grants or revokes the `admin` Firebase Auth custom claim that `reviewIdentityVerification` checks before applying any Tier 2 decision. Manual identity verification needs at least one human who can approve submissions, and nothing in the app can grant that authority by design: the claim lives in Firebase Auth rather than Firestore precisely so no application code path — and no compromised client write — can hand out review authority. Refuses any project outside the three known ones, requires `--yes`, additionally requires `--i-understand-this-is-production` for `tablecrew-prod`, and merges rather than replaces existing claims. Run via `npm run grant:admin -- --project=tablecrew-dev --phone=+91... --yes` (or `--uid=`), with `--revoke` to take the claim away. Add `--create-if-missing` when the reviewer has no Auth record yet — a reviewer is not necessarily an app user, and a fresh project has no accounts until someone signs in through the client. That flag is grant-and-phone only, so a typo cannot silently mint accounts.

**`review_identity.ts`** (Milestone F7, ADR 0007) — the operator client for manual Tier 2 review. `--list` shows every submission awaiting a decision, each with the submitter's date of birth on file (so the reviewer can actually perform the cross-check they are about to attest to) and signed URLs for the two images, falling back to `gs://` paths when the local credentials cannot sign. `--submission=<id> --approve --dob-matches` or `--reject --reason="..."` applies a decision.

It applies decisions by **calling `reviewIdentityVerification`**, not by writing Firestore directly. A direct Admin SDK write would be shorter and would skip the DOB attestation, the apply-time open-report re-check, the image deletion and the audit record — every one of which lives in the callable. Deciding needs `--admin-uid=`/`TABLECREW_ADMIN_UID` and `--api-key=`/`TABLECREW_WEB_API_KEY` (the Web API key, which is not a secret) to obtain an ID token for the admin account.
