# firestore/test/rules/

Firestore security rules tests for `../../firestore.rules`, using `@firebase/rules-unit-testing` against the Firestore emulator — one test file per collection, per `docs/TESTING.md`'s "Testing Firestore Security Rules" section. This is its own npm package (own `package.json`/`tsconfig.json`/`node_modules`), independent of `functions/`, since it tests the rules file directly and has no dependency on the Cloud Functions codebase.

**Milestone F1 status:** real rules now exist in `firestore/firestore.rules` for the five collections F1 scopes in — `users` (public + `private/profile`), `tables` (+ `rsvps` subcollection), `crews`, and `idempotencyKeys` — each with a corresponding test file here: `users.rules.test.ts`, `tables.rules.test.ts`, `crews.rules.test.ts`, `idempotency-keys.rules.test.ts`. `default-deny.rules.test.ts` verifies the trailing catch-all still denies everything else (ratings, reports, venues, splitRequests, and the duressSignals/locationShares/crew-messages subcollections), which get their own real rules and tests in the milestone that builds the feature that needs them (F6/F7 per `docs/IMPLEMENTATION_PLAN.md`), not here.

`fixtures.ts` holds minimal, schema-accurate builder functions for this package's own seeding needs — deliberately not the same fixtures library `docs/TESTING.md` describes for Cloud Functions unit tests (`functions/test/fixtures/`), since that lives in a separate npm package with its own dependency tree and this repo has no monorepo workspace wiring to import across that boundary cheaply. See the doc comment at the top of `fixtures.ts` for the full reasoning.

**Running these tests:** `firebase emulators:exec --only firestore "npm --prefix firestore/test/rules test" --project tablecrew-dev` from the repo root (this is exactly what `.github/workflows/ci.yml`'s `rules-tests` job runs). Requires `npm install` in this directory first — same as `functions/`, this package's `node_modules`/`package-lock.json` need real npm registry access to generate, which the agent sandbox that originally scaffolded this milestone did not have (see `CHANGELOG.md`).
