# features/

One directory per feature, each a self-contained vertical: `presentation/` (screens, widgets), `application/` (Riverpod providers/notifiers), and references into `data/` for repositories — per `docs/ENGINEERING_GUIDELINES.md`'s repository structure.

**Milestone F3:** the Foundation-scope feature set is now named and shelled out — `onboarding/`, `tables/`, `crews/`, `trust/`, `account/` — each with its own README naming the exact `docs/SCREEN_SPECIFICATIONS.md` screens it owns, the `docs/API_SPEC.md` endpoints it'll call, and which later milestone actually populates it. All five are still empty: routes for every screen they'll eventually own already exist in `core/routing/app_router.dart` (pointing at stub placeholders), but no real screen or provider code lands in any of them until the feature milestone that needs it (F5-F8), consistent with Recommendation R7's "don't build ahead of a milestone's actual dependencies." There is deliberately no `discover/` directory, named or empty — Discover is out of scope for the entire Foundation effort, and R7 specifically warns against scaffolding even dormant Discover-adjacent code paths.
